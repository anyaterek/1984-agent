# `mr-review` 0.2 — контекст, серьёзность, риск, стек

Дата: 2026-10-17
Статус: предложение

## Зачем

Скилл прогнали на закрытом рабочем репозитории и разобрали, на какие
опубликованные находки команда отреагировала правкой, а какие отклонила.
Разбор показал четыре системные слабости.

1. **Контекст вне диффа.** Отклонённые находки опровергались тем, что уже лежит
   в репозитории вне диффа: конфигом деплоя, скриптом базы, комментарием рядом,
   спекой, существующим тестом. Ревьюер получает дифф и worktree, но инструкции
   не требуют посмотреть код вокруг и документы проекта до того, как записать
   находку.
2. **Серьёзность занижена.** Ни одного 🔴, хотя были находки, которые по шкале
   самого скилла блокеры: доступ от имени другого пользователя (помечено 🟡),
   сломанный деплой (🟡), нарушенное правило спеки (⚪). Большинство исправленных
   находок были ⚪, хотя ⚪ по определению — «стиль и вкус».
3. **Глубина по размеру, а не по риску.** Режим предлагается только по числу
   строк. Правка CI на несколько строк получает `standard`.
4. **Ревьюер не привязан к стеку.** Роли общие, знание библиотек — из памяти
   модели. Находка «этот API устарел» ни на что не ссылается.

## Цели

- Меньше находок, которые опровергаются кодом или документами вне диффа.
- Цвет находки отражает последствия; доказанность — отдельный фильтр.
- Опасные пути поднимают режим независимо от размера, и решает это скрипт.
- Находки про API библиотек сверены с документацией той версии, что стоит в
  проекте.
- Обратная совместимость: старый `REVIEW.md`, старые вызовы `diff.sh`, токены
  `blocker|major|minor|none` и `tally.sh` работают как раньше.

## Не-цели

- Блокировать мёрж при нерешённых тредах — это настройка проекта в GitLab/GitHub.
- Повторное ревью прошлых находок — отдельное предложение позже.
- Чек-листы под конкретные фреймворки — командные правила живут в `REVIEW.md`.
- Привязка к конкретному инструменту документации.

## Решения

### 1. Контекст проекта — пути в брифе, чтение из целевой ветки

После `git fetch` целевой ветки оркестратор собирает по `git ls-tree` пути
`AGENTS.md`/`CLAUDE.md` (корень и ближайший к каждому каталогу изменённых
файлов, не больше одного на каталог и 10 всего), `CONTRIBUTING.md`, шаблонов
MR/PR и путей из `REVIEW.md` → `Context`. В бриф идут только пути. Читаются
они через `git show <remote>/<target>:<path>`: в worktree лежит версия из MR, и
MR не должен менять правила, по которым его ревьюят. В `standard` то же делает
главный агент.

### 2. «Before you report» и поле `evidence`

Перед возвратом находки ревьюер смотрит папку изменения, вызывающих, похожую
реализацию, соседние тесты и документы из брифа. Опровергнута — не
возвращается; «похоже, так задумано» без `path:line` не считается
опровержением. У находки обязательное поле `evidence` — на чём она держится.
Пустое `evidence` отбрасывается до слияния; при слиянии дублей основания
объединяются; в голосовании `ultra` каждая находка идёт со своим основанием.

### 3. Серьёзность: цвет по последствиям, доказанность только понижает

| Уровень | Что сломано |
|---|---|
| 🔴 | безопасность или ПДн; потеря или порча данных; нарушено правило спеки или контракта; не работает основной сценарий; ломаются сборка, тесты или деплой из-за MR; правило-блокер из `REVIEW.md` |
| 🟡 | дефект с ограниченными последствиями; изменённая логика или её граница без теста; структура; конвенции |
| ⚪ | косметика, которая не мешает и не вводит в заблуждение; стиль, имена, вкус |

🔴 ставится, только если последствие показано: воспроизведено (одноразовый
тест или скрипт в worktree, вывод приложен), упала существующая проверка, или
дословная цитата правила спеки стоит рядом со строкой, которая его нарушает.
Иначе не выше 🟡 с «not demonstrated». Доказанность не поднимает уровень:
кривая рамка воспроизводится каждый раз и всё равно ⚪; та же рамка поверх
кнопки отправки — 🔴.

Отвергнуто: «доказанная ошибка = блокер» — даёт 🔴 за воспроизводимую
косметику; новый уровень для «граница без теста» — ломает `tally.sh`.

### 4. Опасные пути — в `diff.sh`

`diff.sh` печатает `risky: <file> (<reason>)` для каждого изменённого файла,
включая пропущенные фильтром:

- `ci` — `*.gitlab-ci.yml`, `.gitlab/ci/*`, `.github/workflows/*`
- `deploy` — `*Dockerfile*`, `*Containerfile*`, `*compose*.yml`, `*compose*.yaml`, `*deploy*`
- `migration` — `*migrations/*`, `*migration/*`
- `auth` — `*auth/*`
- `review-rules` — `REVIEW.md`, `AGENTS.md`, `*/AGENTS.md`, `CLAUDE.md`, `*/CLAUDE.md`
- `REVIEW.md` — globs из `REVIEW.md` → `Risky paths`, передаются через `--risky <glob>` до base-ref

Есть строка `risky:` → предлагается не ниже `hard`; выбран `standard` —
первая строка отчёта это говорит.

### 4a. Ключевые пути и контексты — тоже в `diff.sh`

Опасные места не единственный риск: MR, который задевает сразу несколько
ключевых путей пользователя, ломает связку, которую отдельный ревьюер целиком не
видит. Идеи: ключевые пути пользователя (Critical User Journeys, Google SRE),
ограниченные контексты (bounded contexts, DDD), тестирование по риску (ISTQB:
риск = вероятность × последствия).

Команда один раз описывает в `REVIEW.md` разделы `Journeys` и `Domains`:
`- <имя>: <glob>, <glob>`. Оркестратор передаёт каждую пару в `diff.sh` как
`--journey '<имя>=<glob>'` / `--domain '<имя>=<glob>'`, скрипт печатает
`journey: <имя> (<n> files)` и `domain: <имя> (<n> files)`. Правило: 1 путь
или 1 домен → не ниже `hard`; 2+ путей или 2+ доменов → предлагается
`ultra`; итог — самый глубокий режим из размера, опасных путей и путей. Если
выбран режим ниже, отчёт начинается строкой с рекомендацией `ultra`.

Отложено: связанность изменений по истории git (change coupling).

### 5. Стек — манифест и lock-файл от скрипта, версия в `evidence`

`diff.sh` печатает `manifest: <path> (lockfile: <path>|none)` для манифестов,
которым принадлежат изменённые файлы. Lock-файл ищется своей экосистемы
(`package.json` → pnpm, bun, yarn, npm; `pyproject.toml` → uv, poetry; и т.д.)
рядом, затем выше. Поиск — один `git ls-tree` и один проход awk. Версии скрипт
не разбирает: форматы lock-файлов разные, на shell это хрупко.

Находка про API, устаревание или идиому библиотеки ссылается на документацию
версии из lock-файла (рантайм — из `engines`, `.nvmrc`, `.tool-versions`,
`requires-python`, `go`, `rust-toolchain`; версия на машине ревьюера не
годится). Источник — инструмент документации, если он есть у агента, иначе
официальный сайт; не сверено — не выше 🟡 с «not verified against docs».

  (`evals/results/2026-10-17.md`).

## Риски

- Ревьюеры читают больше → дольше. Документы передаются путями и читаются по
  необходимости.
- `*deploy*` и `*auth/*` ловят лишнее. Это только нижняя граница режима, не
  находки.
- Eval недетерминированы — фиксируется прогон с датой, как и раньше.

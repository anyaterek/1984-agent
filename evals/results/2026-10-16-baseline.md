# Baseline (no skill) — 2026-10-16

Two fresh general-purpose agents, fixture from `evals/make-fixture.sh`, plain request
«отревьюй ветку X (MR в main), прогони тесты и сборку, дай отчёт».

## B1: `logic-bug`

- Isolation: used `git worktree add --detach` on its own, no checkout; tree left clean. ✅
- Baseline: ran tests on `main` and the branch, `legacy` correctly called pre-existing. ✅
- Found: `>= 100` blocker, `roundPrice` without tests, float rounding issue, `x2` naming, unused function. ✅
- Shape: free-form report, own severity words («Блокер», numbered list), table of test results.

## B2: `env-dependent`

- Isolation and baseline comparison: same as B1. ✅
- **Diverges from spec:** the test failing on missing `DATABASE_URL` was counted as
  «новое падение» and drove a «не мёржить» verdict. Spec: environment failures are
  `env-unverified`, never a blocker by themselves (the test's quality may still be a finding).
- Shape: different from B1 (verdict at the end, different headings, no severity scale).

## Conclusions for the skill

1. Agents already isolate and compare against the target branch unprompted — the skill
   states these as a short recipe, no prohibition lists needed.
2. The real gaps are **shape and policy**: one severity scale, one report layout,
   env-failure classification, modes, publish-only-after-confirmation. Write them as
   contracts/templates (recipe form), not as "don't" rules.
